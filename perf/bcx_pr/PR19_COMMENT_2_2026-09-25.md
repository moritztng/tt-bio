jax 0.11.2, python 3.12, CPU backend. `design_devices()` is stubbed, since there is no accelerator
on this machine; everything else is the module as written. So cases B and D rest on jax ids being a
dense enumeration of what the process can see, which is what I measured here
(`XLA_FLAGS=--xla_force_host_platform_device_count=4` gives `cpu:0` through `cpu:3`) and the reason
for the one-line check on a real box:

```bash
CUDA_VISIBLE_DEVICES=2,3 python -c "import jax; print(jax.devices())"
```

If that prints ids 0 and 1, B and the first D hold. If it prints 2 and 3, only A and the dead
`None` handlers do. The other three cases pass either way and are there to hold the behaviour that
already works.
