WHY rc=1 AT THE ANALYSIS STEP IS EXPECTED, NOT A BROKEN REFERENCE.

  REF_VALID_DONE size=512 rc=1 wall_s=5345

The run is `--steps design inverse_folding design_folding analysis`, which deliberately skips
the whole-complex `folding` step (that is where the CPU hours go and it feeds no metric this
row reads). Re-running the failed step by hand prints the cause:

  Folded path does not exist. Skipping: .../intermediate_designs_inverse_folded/fold_out_npz/bg512.npz
  Computed metrics successfully for 0 out of 1.
  analyze.py:275 in aggregate_metrics -> assert len(sample_ids) > 0  -> AssertionError

So the aggregate CSV is unwritable BY CONSTRUCTION on a 4-step run: analysis wants the
complex-fold npz we chose not to compute, skips the only sample, then asserts on an empty
list. The designability number is already fixed at step 4 (`refold_design_cif/`), which is
what `scrmsd.py` reads and what `scrmsd.py --check` reproduced against the pipeline's own
column on a run that did reach analysis. Both 1536 references and both `_b` twins will end
rc=1 the same way. Score them from disk; do not read rc=1 as a failed reference.
