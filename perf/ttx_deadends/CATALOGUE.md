# TTX dead-end catalogue — levers that died on CAPABILITY, ranked

Two campaigns (`b2z` wave 1, `b2z2` wave 2) and the `roof-*` and `b2x-*` rows before them produced a
large set of measured dead ends. This is the subset that did **not** die on physics. Each row died
because ttnn 0.68.0, or a gate in our own tree, would not let the work be expressed, and each
already carries a number from its original screen. That makes this a ranked unlock list, not a wish
list: a newer runtime can resurrect some of these and the price is already known.

Assembled by `ttx-deadend-catalogue`, 2026-09-14, from `state/concluded/*`, `state/b2z/FINDINGS.md`,
`state/b2z2/{FINDINGS,CLOSING}.md`, `perf/*/`, the memory directory and the recorded blockers in
`tt_bio/*.py`. **No row here was tested against a new build.** Every number is a quote from the run
that measured it.

## How to read the value column

An op ratio is not a fold second. `1.6652x` on the trimul was 0.445 s; a 1.068-1.301x op lever was
NO-GO at 1.06 ms of the cell. The two tables below are ranked separately for that reason and must
not be merged. Where a row has both, the fold number wins and the op number is context.

`LEVEL` is one of **fold** (whole `model.fold`, paired A/B), **block** (one Pairformer or diffusion
step, ~200 of them in a fold), or **op** (one call, in isolation).

## Who blocks what

| class | meaning | a new ttnn build helps? |
|---|---|---|
| **TTNN** | the runtime refuses the expression | yes, this is the campaign's target |
| **OURS** | our own gate, one line of Python | no, and it needs no build either |
| **METAL** | needs a dataflow/compute kernel change under ttnn | only if upstream wrote it |
| **MEASURE** | nothing refuses it; the number to justify it was never taken on the cell | no |
| **RETIRED** | measured and refuted after the seed entry was written | no, do not re-price |
